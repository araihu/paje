# Public site surface brief

Primary user and task: Engineer assessing whether Pajé can safely carry an agent-driven code change from request to artifact or draft pull request.

Usage scene and constraints: Read-only public site; canonical English, Brazilian Portuguese, and Spanish documents; root locale negotiation; static output only.

Product register: brand.

Archetype: public technical product explainer.

Information priority: durable workflow promise, execution boundary, current beta scope, repository documentation.

Navigation model: document links.

Consequential states: none; all interactions are links.

Existing identity: preserve supplied marks and paper, ink, and blue document-workflow register.

Density: relaxed.

Motion: restrained; one optional workflow-marker transition, disabled for reduced motion.

Visual direction: a durable-run ledger rather than a generic SaaS landing page. Large editorial claim, crisp technical evidence, and one structured execution record make the promise concrete.

Chosen Goshtoso primitives: `head.DependenciesMinimal` for version-matched local assets and `badge.Badge` for the beta state. The public document composition remains application-owned because no public content pattern matches it.
