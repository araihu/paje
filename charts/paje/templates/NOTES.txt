Pajé coordinator {{ include "paje.fullname" . }} has been installed.

The coordinator connects outbound to Hatchet and exposes no Kubernetes Service.
Inspect it with:

  kubectl logs -n {{ .Release.Namespace }} deployment/{{ include "paje.fullname" . }} --follow

Beta workflow:
  Hatchet workflow: paje-code-change-v1
  Template:         code-change@v1
  Phases:           resolve -> execute -> approval -> publish -> finalize
  Input envelope:   {"run_id":"<generated-once>","input":{<code-change@v1>}}

Reuse run_id for transport retries. Hatchet holds it with status-based
idempotency until the workflow is terminal, with a 30-day fallback cap. The
nested template input remains provider-neutral and strictly validated.

Artifact mode is the default and durably skips approval and publication.
Pull-request mode requires an artifact-bound Hatchet event:

  key: paje:approval:<run-id>
  body:
    {
      "run_id": "<run-id>",
      "artifact_digest": "<64-hex-digest>",
      "approved": true,
      "actor": "<operator>",
      "decided_at": "<UTC-RFC3339-time>",
      "reason": "<optional approval reason>"
    }

  reason is optional when approved is true; it is mandatory and non-empty when
  approved is false.

Every active Hatchet, Mem0, and GitHub credential must use a distinct Secret,
including generated service Secret names. Worker credentials belong in the
external binding catalog, never in this coordinator Deployment. Agent and
verification children cannot receive service credentials; only the publisher
receives GitHub credentials. Before reading
configuration, the worker makes itself non-dumpable; combined with the chart's
dropped capabilities and noNewPrivileges setting, same-UID children cannot
inspect the credential-bearing parent. Startup fails if the guard cannot be
installed.

Idempotency keys bind code-change@v1 plus the canonical input hash. Exact reuse
resumes the run; changed input conflicts. GitHub publication uses
paje/code-change/<run-id>, normal non-force push, and exact run/base/artifact
trailers. Conflicting remote state fails closed. Pajé never merges or pushes the
target branch.

Inspect one persisted artifact:

  RUN_ID=<run-id>
  RUN_FILE=/var/lib/paje/runs/runs/$RUN_ID.json
  DIGEST=$(jq -r .artifact.digest "$RUN_FILE")
  ARCHIVE=/var/lib/paje/artifacts/sha256/${DIGEST%${DIGEST#??}}/$DIGEST.tar.gz
  tar -xOzf "$ARCHIVE" manifest.json | jq .
  tar -xOzf "$ARCHIVE" verification.json | jq .

Acceptance opt-ins:
  Docker: PAJE_DOCKER_ACCEPTANCE=1 plus an explicit local Unix endpoint
  Codex:  PAJE_DOCKER_ACCEPTANCE=1 and PAJE_CODEX_ACCEPTANCE=1
  GitHub: PAJE_GITHUB_ACCEPTANCE=1, PAJE_GITHUB_TOKEN,
          PAJE_GITHUB_TEST_REPOSITORY, PAJE_GITHUB_TEST_BASE_REF,
          PAJE_GITHUB_TEST_RUN_ID
  Kubernetes server dry-run: PAJE_KUBE_ACCEPTANCE=1 and an explicitly verified
          non-production context

Beta is intentionally one replica because filesystem stores use process-local
compare-and-swap. Non-goals are a YAML DSL, auto-merge, tags/releases,
GitOps/monitoring, Forgejo, Kubernetes Jobs, and multiple replicas.
